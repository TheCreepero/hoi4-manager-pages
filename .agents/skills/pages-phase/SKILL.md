# /pages-phase <id> [<scene> ...] [from <stage>]

You are the orchestrator of one phase (`<id>` is the roadmap id, such as `A3` or `E2`; the scenes are the `tools/scenes/*.json` names it touches). Invoking this skill is the user's standing request to spawn the agents named below; spawn no other kind. Read `wiki/Workflow.md` first (the stages and the handoff files), then `AGENTS.md`, `wiki/Working-Rules.md` sections 3 and 7 only, the phase's row in `wiki/Roadmap.md` (grep the id; do not read the page) and its notes in `wiki/phases/<id>.md`. `wiki/Design-Rules.md` holds the recipe steps; read a section when a gate needs it, not the page. For a scripted page add the "rules" section of `wiki/Scripted-GUIs.md` and the page's own section there and in `wiki/Roleplay-Pages.md`. Look `wiki/Engine-Facts.md` up by row (W34, X66) when a rule cites one; do not read it whole.

Find where the phase stands before doing anything: `wiki/phases/<id>.md` (its sections and the last dated line), `scratch/phases/<id>/` (which handoff files exist), `git status`. Continue from there; `from <stage>` overrides.

## Stage checklist

Tick each stage in your own working notes as it closes. Never skip a user gate.

1. **Open.** Phase notes from `wiki/Phase-Template.md` if missing (fill Scope and "Roles and handoffs"). `scratch/phases/<id>/` created. `contracts.md` written: taken hotkeys (`grep -rn 'shortcut = "' interface/ tools/build_managers.py tools/build_records.py`), new hotkeys, shared rows and windows, shared files and owners, shared frames. Builder: `builder-script`, the only builder here (every component is a scripted page; the vanilla screens and their `builder-screen` are the 1440p UI mod's). One screen: main tree; several: one worktree per builder, made as `wiki/Contributing.md` says. The window's section exists in the Manager's `Artifacts/executable/window-bindings-1440p.md` or `window-bindings-all.md`; if not, regenerate the reports (`Scripts\Executable\Update-HoiExecutableReports.ps1`) before the designer starts, so nobody reads the decompiled code inside the phase.
2. **Design.** Small phase (the verdict would be `refine` at effort S: a card pass, a chip, a hotkey, a width, a caption): no designer; write `layout.json` and `design.json` yourself with one figure group (`python -I tools/mockup.py <layout> --out ... --crop ...`), the linter and `tools/ux_audit.py` run, the review questions the change touches answered (H4 always), note "short path" under "Roles and handoffs", and go to stage 3; spawn the designer after all when the work grows (a second group, a moving window, a changed list). Otherwise spawn `designer` with: the id, the scenes, the output folder, the contracts path, what the user asked for in their own words, the shapes of `layout.json` and `design.json` copied from `wiki/Workflow.md` "Handoff files", the figure groups you want (four at most), and the reply length. Background it; do other preparation meanwhile.
3. **Gate A.** Check `design.json`, `layout.json` and the figures against the points of `wiki/Workflow.md`, stage 3: run `python -I tools/lint_layout.py scratch/phases/<id>/layout.json` and `python -I tools/ux_audit.py <id>` yourself, and read the tasks, the review answers, the contrast table and the squinted figures. Run `python -I tools/make_design_page.py <id>` and read `scratch/phases/<id>/figures/<group>.webp`, one image per group, with the Read tool (the 1:1 PNGs only where a measurement is in question). Send what fails back to the same designer with `SendMessage`, naming each point. Then publish `scratch/phases/<id>/design.html` with the Artifact tool; put the link into the phase notes under "Roles and handoffs" and run `python -I tools/phase_notes.py <id>` (the Proposal section).
4. **User gate 1.** Give the user the link and the numbered decisions. Stop here until they answer. Then write the answers, dated, under "Decisions" in the phase notes and into `decisions-final.json`.
5. **Build.** Spawn the chosen builder with: the id, the tree to work in, the paths of `layout.json`, `design.json`, `decisions-final.json`, `contracts.md`, the scenes, the shape of `build.json` copied from `wiki/Workflow.md`, and the reply length. Background it.
6. **Gate B.** `python -I tools/build_managers.py --check` is clean. Read the whole `git diff` of the generated files yourself (`interface/mod1440_*.gui`, `common/`, `localisation/`) and every line of it. Run `tools/ux_audit.py <id>` again (the squinted figures now carry the build). Open every `build-<group>.png` beside its mock-up (or run `make_design_page.py` again and read the composites, which now carry the build). Read the deviations and `build.json`. Run `powershell -File .\build.ps1 -Check <scene>` yourself once if the builder's report does not show a green run. Send what fails back to the same builder. Publish the page again (same artifact URL) and run `tools/phase_notes.py <id>` (the Build section).
7. **User gate 2.** Ask for the launches in one message: the scenes, the number of launches, whether time will run (ten days at most, autosave copied) and whether a playset mod will be loaded. Stop until the user grants it. A vague grant is not a grant: ask again naming the launches.
8. **Check.** Spawn `game-checker` with the user's grant quoted, the id, the `gameCheck` line and the scenes, the round number, the shape of `check-<n>.json` copied from `wiki/Workflow.md`, and whether `-DevLink` is in place. Wait for it; nothing else uses the screen meanwhile.
9. **Capture review.** Read the checker's `check-<n>.json`, every evidence cut it names (`scratch/phases/<id>/checks/evidence-*.png`) and one overview capture per scene; open a whole crop only where a cut leaves a doubt. Run `tools/phase_notes.py <id>` (the Game checks rows). Decide per finding: defect, renderer blind spot that the game settled, or the user's to judge. Defects go to the same builder (`SendMessage`), with the evidence paths; a cause nobody knows goes to `builder-script` as well. The builder records the fixes in `fixes.json`; after the fix, gate B again (and `phase_notes.py`, the Fix rounds), then the checker again for the scenes the fix touched (within the grant, or ask again). Repeat until clean.
10. **Report, user gate 3.** One message: what was built; the design page link, now with build renders; the checks (how many, with which mods loaded, what they showed); the numbered list of what only the user can settle (tooltips, click targets, states a 1936 start does not show, widths); the files changed, uncommitted. Stop. The user tests in their own game and commits.
11. **Close**, when the user says the phase is done: recipe step 8 of `wiki/Design-Rules.md`; `newFacts` of every handoff into the knowledge register with `Add-HoiKnowledge.ps1` or dropped with a reason; `Export-HoiKnowledge.ps1 -Repo hoi4-manager-pages`; `-SaveReference` with the user's grant; Roadmap, README, Workshop text, `version`.

## Rules for the orchestrator

- Continue an agent with `SendMessage` while it exists; spawn a new one only when it is gone. Each agent starts cold, so the brief names every file and section it needs, carries the handoff shapes it writes, and names nothing it does not need; an agent reads the wiki for exceptions, not whole.
- Never start the game yourself and never let an agent start it without the user's grant for exactly those launches. Never commit; the user does.
- Review means reading the artefact, not the agent's summary of it: the JSON, the composite image of every group, the layout compare, the baseline diff, the test output.
- The page is made, not written: `tools/make_design_page.py`, never a page script of your own. The notes' Proposal, Build, Game checks and Fix rounds sections are made too: `tools/phase_notes.py <id>` at every gate; you write Scope, Roles and handoffs, Decisions and Close by hand, and the user's own tests under the Game checks markers.
- You alone write the knowledge register and `wiki/Roadmap.md`, `README.md`, `descriptor.mod`, `AGENTS.md`.
- Log every launch and every decision in `wiki/phases/<id>.md` the day it happens; the handoff files under `scratch/` are not in the repository.
- When the user brings issues from their own game (a list, screenshots), enter at stage 9 with them as findings.
