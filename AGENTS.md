# HOI4 Manager Pages - Agent Rules

Shared rules for every mod in this tree (file encodings, build commands, engine knowledge, git) are in the Modding Manager's `../../AGENTS.md`; `CLAUDE.md` and `GEMINI.md` import this file. This file holds the short form of the rules that always apply; `wiki/Working-Rules.md` is the long form, and the `/pages-phase` skill reads the pages a phase needs at its start.

## What this mod is
- Standalone scripted GUIs for Hearts of Iron IV at 2560x1440: the manager pages (Army Readiness, States, National Figures with History, the top bar strip; Milestone D of `wiki/Roadmap.md`) and the Records window for role-play (War Diary, Officers, Government, Wars, the state card and the unit honours; Milestone E, `wiki/Roleplay-Pages.md`). What each page shows: `wiki/Scripted-GUIs.md`.
- Split from the HOI4 1440p UI Mod on 2026-10-21 (user decision); the reworked vanilla screens stay there. The names stay: every `mod1440_*` file, window, variable and effect and every `GFX_1440p_SG_*` and `GFX_1440p_medal_*` sprite keeps its name, because the variables live in players' saves. No dependency on the 1440p mod: phase D8 makes National Figures and Army Readiness free windows so that no page needs its override files (X6, X7). `tools/Invoke-GameCheck.ps1 <scene> -WithScreens` checks a page with both mods loaded.
- The script lives under `common/` and changes the checksum: no Ironman, no achievements, every multiplayer player needs the mod (user decision, 2026-10-12). Nothing goes under `common/` but the four folders `scripted_guis`, `scripted_effects`, `on_actions`, `synchronized_dynamic_tokens`, every file named `mod1440_*`; `events/`, `history/` and `map/` stay empty; `tests/GuiInvariants.Tests.ps1` and `tests/ScriptedGuis.Tests.ps1` hold the line.
- The hotkeys Shift+M (fold or open the page of the open tab) and Shift+J (the Records) are reserved for this mod (`tools/hotkeys.json`); no screen of the 1440p mod uses them.
- `tools/` (the generator, inspection, render and harness scripts), `reference/` (captures of the pages and of the frames they draw over) and `scratch/` (git-ignored) are dev-only and never ship.

## Mod invariants
- The mod is built one page per phase through the `/pages-phase <id>` skill, with four roles (the orchestrator, and the agents `designer`, `builder-script` and `game-checker` defined under `.claude/agents/`) and the user's three gates: the design page, the launches, the final report (Working-Rules section 7). The notes' Proposal, Build, Game checks and Fix rounds sections are generated from the handoff files by `tools/phase_notes.py`.
- The rules of `wiki/Scripted-GUIs.md`, one line each: (1) a button shows, navigates or keeps a record: it changes its page, moves the camera or writes the mod's own variables, arrays, flags and the lines the game keeps for show, on the player's click or a switchable hook, never anything the game charges for (`tests/ScriptedGuis.Tests.ps1` holds the list of allowed commands); (2) own country only, every scripted GUI is `player_context`; (3) every value is checked against the game's own number before a page ships, and the check is logged in the phase notes; (4) the map is one key away: Shift+M hides and shows the page of the open tab, which remembers per country whether it is open; (5) no loop in anything drawn every tick: counting runs on a click, once a day or once a month, a long list through `dirty`; (6) vanilla content only: equipment kinds, buildings, resources and modifiers are named in the mod's files; (7) names carry the prefix `mod1440_` (windows, files, variables, effects), sprites `GFX_1440p_SG_*`, and the art is vanilla sprites and textures, never AI-generated images; (8) the AI never looks: `ai_enabled = { always = no }` on every one.
- `python -I tools/build_managers.py` writes every file of the pages and the Records window (`interface/mod1440_*.gui`, `common/**/mod1440_*.txt`, `localisation/*/mod1440_l_*.yml` and `mod1440_traits_l_*.yml`, `tools/scenes/<page>.json`); the Records window is in `tools/build_records.py`, which it imports. Change the tools, never their output; `--check` and the test suite fail while the output is stale. New sprites are `GFX_1440p_*` in `interface/mod1440_ui.gfx`, with this mod's own textures under `gfx/interface/mod1440/` (cut from vanilla ones by `tools/stretch_background.py`); vanilla sprite names are never declared again.
- `python -I tools/make_game_tables.py` refreshes the tables of characters and victory points after a game update (`--mods` for the playset's), `python -I tools/list_medals.py` the medals; a test fails while they differ from the game.
- Officers are reached with `every_army_leader` and `every_navy_leader` and kept through `mod1440_of_me`, never `THIS` (X66). Every name after `@` is listed in `common/synchronized_dynamic_tokens/mod1440_tokens.txt` (the generator does it, X24). Localisation `.yml` files are UTF-8 with BOM, every other text file UTF-8 without.
- Render before asking (`python -I tools/render_gui.py --scene <page>`), and never start the game, or let an agent start it, without the user's grant for exactly those launches; a check saves nothing, stays in January 1936 and runs at most ten days with `autosave.hoi4` copied and hashed. Log every launch in `wiki/phases/<id>.md`.
- `tools/GameHarness.ps1` simulates input and copies the screen to PNG, nothing more (Windows Defender once flagged it); image conversion belongs in the Python tools. If the antivirus flags a tool, tell the user; never disguise it, add exclusions or restore from quarantine.
- Never change `hoi4.exe` on your own: a patch is the user's decision and goes through the Manager's scripts. What a launch teaches goes into the register with an alias of its Engine-Facts section (`-Alias 1440p:X74`), then `Export-HoiKnowledge.ps1 -Repo hoi4-manager-pages`.

## Commands beyond build.ps1
- `powershell -File .\build.ps1 -Check <scene>` (validation, the Pester suite and the scene render; `-InGame` adds the unattended game check); `tools/Invoke-GameCheck.ps1 <scene> [-WithScreens]`, `tools/Invoke-GameSteps.ps1`, `tools/Show-GuiOutline.ps1`; `python -I tools/build_managers.py [--check]`, `tools/make_game_tables.py [--check] [--mods]`, `tools/list_medals.py --sprites`, `tools/check_effects.py` (throwaway effects for a check), `tools/check_playset.py` (where the launcher's playset meets the pages), `tools/render_gui.py --scene <page>`, `tools/mockup.py <layout>` (the mock-up from the layout file), `tools/lint_layout.py <layout>` (the layout against the ruleset of `wiki/Design-Language.md`), `tools/lint_gui.py` (the written pages against it; their listed deviations are `tools/design_exceptions.json`), `tools/ux_audit.py <id>`, `tools/make_design_page.py <id>` (the design page from the handoff files), `tools/phase_notes.py <id>` (the generated sections of the phase notes), `tools/crop_capture.py` (an evidence cut of a capture), `tools/save_reference.py --index`.

## Read when
| Task | Read |
|---|---|
| Starting or continuing a phase | the `/pages-phase` skill, which reads `wiki/Workflow.md`, `wiki/Roadmap.md`, `wiki/Working-Rules.md` and the phase notes |
| Working on a page | `wiki/Scripted-GUIs.md` ("Rules", the page's section, "Working on a page"), `wiki/Roleplay-Pages.md` for the Records, `wiki/Script-Reference.md` for the script language; Working-Rules section 2a |
| Designing a page | `wiki/Design-Language.md` (the design ruleset), `wiki/Workflow.md` "Handoff files" (`layout.json`), the Manager's bindings reports by window (`window-bindings-all.md`; never the decompiled code inside a phase) |
| Seeing a result, a game check, a recipe | Working-Rules section 3, `wiki/Game-Recipes.md`, `reference/README.md` |
| Another mod in the user's playset | `wiki/Compatibility.md`, `python -I tools/check_playset.py` |
| What the engine does | `wiki/Engine-Facts.md` by row (X6, X66), or `Find-HoiKnowledge.ps1 -Id <row>` |
| Publishing to the Workshop | `WORKSHOP_DESCRIPTION_GUIDELINES.md` |

## Engine Knowledge
- Engine facts live in the Modding Manager's register, reached through the user-level `hoi4-modding-knowledge` skill: search it before a new kind of file and before asking for a game launch, cite ids here, never write a fact into this repository. This mod's pages `wiki/Engine-Facts.md`, `wiki/Script-Reference.md` and `wiki/Roleplay-Pages.md` are generated from the register, and their row ids (W14, X23) are record aliases, so both forms resolve.
- Topics this mod leans on: `scripted-gui`, `script-language`, `localisation`, `gui-widgets`, `gui-layout`, `gui-sprites-and-fonts`, `loading-and-overrides`, `game-automation`, `engine-limits`.
- The interface skill is the user-level `hoi4-gui-modding`; this repository keeps no copy. `tests/Knowledge.Tests.ps1` runs the register's audit for this repository; it is a copy the Manager keeps current.
